# 分阶段提示词

按 docs/spec.md「MVP 9 周拆解」分成 6 段：第 0 步搭工程，阶段 1–5 对应第 1–9 周。每段的提示词直接复制到 Claude Code 里用，「……」的地方换成你的内容。提示词里说的「设计稿 Home」等，指 docs/design/README.md 里的文件名。

## 怎么用 Claude Code 跑这些提示词
- **一个阶段开一个新会话**，或者先输入 `/clear`。上一阶段的聊天记录会占地方，还会让它分心。
- **大任务先进计划模式**：按 `Shift+Tab` 直到状态栏显示 `⏸ plan mode on`，这时它只读资料、出计划，不改文件。按 `Ctrl+G` 可以直接编辑计划。你确认后再让它写代码。
- 提示词里的文件可以用 `@` 引用，比如 `@docs/decisions.md`，它会先读那个文件。
- 跑偏了按 `Esc` 打断；按两下 `Esc` 或输入 `/rewind`，可以回到之前的对话和代码。同一个问题纠正两次还不对，就 `/clear`，把学到的东西写进新提示词重来。
- 起步包里带了两个命令：`/design-check 页面名` 对照设计稿走查，`/phase-done 阶段号` 做阶段验收。审查改动也可以用 Claude Code 自带的 `/code-review`。
- 小程序的界面 Claude 看不到。第 0 步会搭一个 H5 预览让它自己截图；分享卡片、订阅消息弹窗这类微信专属的效果，要你在微信开发者工具或真机上看，截图贴给它。

## 第 0 步 · 搭工程（约 1 天）

```text
先读 CLAUDE.md、docs/decisions.md，以及 docs/spec.md 的「技术方案」「数据模型」两节。然后在计划模式里给我第 0 步的搭建计划，我确认后再动手：

1. pnpm workspace 单仓：apps/miniapp（uni-app + Vue 3 + TypeScript + Vite，编译微信小程序，另配一个只在开发时用的 H5 预览）、apps/server（NestJS）、packages/shared。
2. 统一 TypeScript、ESLint、Prettier。小程序端和 shared 用 Vitest；后端用 NestJS 默认的 Jest 还是 Vitest，你选一个并说明理由。
3. 后端连 MySQL 8 和 Redis，本地用 docker compose 起；推荐一个 ORM 并说明理由；配好数据库迁移。
4. 微信能力做成适配器接口：登录、云托管身份、订阅消息、内容安全、分享配图生成。先写本地假实现，假身份要能切换成不同的测试用户。
5. 小程序端统一的请求层：正式环境走 wx.cloud.callContainer，本地开发走 localhost，H5 预览走假数据。
6. 打通一条最小链路：小程序首页调 GET /api/v1/health 并显示结果，H5 预览也能打开。
7. 写一个用 Playwright 给 H5 预览截图的脚本，以后对照设计稿用。

验收：装好依赖后，一条命令能起后端、一条命令能编译小程序、一条命令能打开 H5 预览；测试、类型检查、lint 都能跑通。做完把这些命令补进 CLAUDE.md 的「常用命令」，然后提交。
```

## 阶段 1 · 第 1–2 周：主题、组件、登录、群组

```text
这个阶段做三套主题和基础组件、登录、群组。先读：
- docs/design/README.md 和 docs/design/tokens.json
- 设计稿 Main、ThemePicker、Login、Groups、GroupHome、GroupSettings、Invite、JoinLanding 的三套截图和 HTML
- docs/spec.md 的「功能规划 · 群组」「视觉、动效与文案风格」「信息架构与页面清单」

要做：
1. 主题系统：把 tokens.json 生成三套 CSS 变量；主题 store 默认贴纸风，切换后保存到用户设置并在本地缓存。
2. 插画：从设计稿 HTML 的 <symbol> 里取鸽子、鸽子头套、皇冠、鸽屎、火锅等 SVG，三套主题各一份。
3. 基础组件：按钮（主、次、危险）、标签、卡片、头像（含鸽子王头套版）、底部弹出的确认卡、顶部导航、底部导航、空状态。再做一个组件演示页，可以切换三套主题看。
4. 登录：wx.login 换登录态，建用户；第一次进来用头像昵称填写组件设置头像和昵称。
5. 群组：建群、群组列表、群组主页（鸽榜先用假数据）、群设置、邀请（卡片和邀请码，海报可以先占位）、加入落地页、退群和移除。数据表按 docs/spec.md「数据模型」。

先在计划模式里给我方案：组件清单和参数、接口、数据表、页面路由。我确认后再写。

验收：
- 组件演示页三套主题都对得上设计稿 Main（跑 /design-check Main）
- 群组相关页面每页跑一次 /design-check
- 群组接口有接口测试，邀请码、退群规则有单元测试
- 最后跑 /phase-done 1
```

## 阶段 2 · 第 3–4 周：时间文案、发起计划、计划详情、表态

```text
先读 docs/spec.md 的「核心概念与状态模型」「功能规划 · 计划」「功能规划 · 表态」「业务规则与边界情况」，以及设计稿 Home、CreatePlan、PlanDetail、JoinSheet、Flake、Calendar、KingPublish。

要做：
1. 时间文案工具（packages/shared），先写测试：按 docs/spec.md「时间文案规则」把用例写全——今天、明天、后天、本周X、下周X、周X；六个时段；跨天活动；倒计时四档；群时区和手机时区不同时加一行「你的当地时间」；跨年；悉尼夏令时切换那天。先跑一遍确认测试失败，再写实现，直到全部通过。
2. 表态状态机（packages/shared 加后端）：pending、in、out、flaked、waitlist、reconfirm 之间怎么转，按 docs/spec.md 写成纯函数，每种转换都有测试；表态接口用 request_id 做幂等。
3. 发起计划：9 种类型、时间快捷选择、地点、详情、人数、报名截止；重大修改要已跟的人重新确认；取消；再来一局。
4. 计划详情：成局状态、头像墙、跟了 / 鸽了 / 不跟 / 未表态、变更记录。
5. 确认卡：跟了、不跟、鸽了共用一个组件，内容按 docs/spec.md「确认卡必须展示的信息」；跟了 5 分钟内可撤回；候补递补；带朋友；时间冲突提醒；发起人不能鸽自己的计划。
6. 发布成功页、首页、日历。

先在计划模式里给我方案，我确认后再写。

验收：时间文案和状态机测试全过；每个页面跑 /design-check；用两个测试用户走一遍「发起 → 跟了 → 撤回 → 再跟 → 鸽了」，每一步给我看截图或接口返回。最后跑 /phase-done 2。
```

## 阶段 3 · 第 5–6 周：鸽子王、通知、分享卡片

```text
先读 docs/spec.md 的「功能规划 · 鸽子王与趣味系统」「功能规划 · 提醒与通知」「定时与延时任务」，docs/decisions.md 第 16、17 条，以及设计稿 Reveal、KingPublish、KingPlan、GroupHome、Notifications、ShareCard、ShareChat。

要做：
1. 鸽值：按 docs/spec.md「鸽值计算」实现。鸽值算在点下「鸽了」那一刻所在的周；免鸽卡；回归后作废；退群导致的鸽了。全部写单元测试。
2. 每周评选：Worker 每 15 分钟扫一次，找当地时间刚过周一 00:05 的群组结算；平局规则、和平周、群里可关闭；周一 10:00 发揭晓通知。用假时钟测跨时区和夏令时。
3. 揭晓页和鸽子王头套（挂一整周）；鸽王发布成功页的鸽屎特效；群友打开鸽王局时点鸽屎擦掉。动效要能在设置里关掉。
4. 订阅消息：在用户自然点击的时刻申请，按「用户 × 模板」记额度，额度紧张时按优先级发；所有通知都进站内通知中心，按计划聚合；催一下。
5. 分享卡片配图：点「发到微信群」时用画布当场生成 5:4 配图（1000 × 800），按分享人的主题画，四种状态见设计稿 ShareCard；3 秒内出不来就用默认图；标题按规则自动生成。
6. 顺带实测动态消息，不并进主流程：写一个最小演示，确认个人主体能不能用、activity_id 24 小时过期后卡片显示什么、「已到齐」状态能不能用。结论写到 docs/decisions.md 第 17 条下面，先给我看。

先在计划模式里给我方案，我确认后再写。

验收：鸽值和评选测试全过；用假时钟演示一遍「鸽了 → 周一结算 → 揭晓」；四种分享配图各生成一张给我看，和设计稿对照。最后跑 /phase-done 3。
```

## 阶段 4 · 第 7–8 周：免打扰、内容安全、埋点、我的和设置、走查

```text
先读 docs/spec.md 的「免打扰」「安全、隐私与合规」「数据指标与埋点」，以及设计稿 Profile、Settings、ThemePicker、Onboarding、Notifications。

要做：
1. 免打扰：用户设时段，时段内的通知延后到当地 08:00 补发。
2. 内容安全：群名、昵称、计划标题、详情、鸽了理由过文本检测，头像和群头像过图片检测，不通过时给友好的提示；加举报入口。
3. 埋点：按 docs/spec.md「埋点事件」实现，事件名和属性保持一致。
4. 我的、设置（通知与免打扰、动效开关、主题入口、隐私、注销）、主题选择页、新手引导 3 屏。注销后 7 天内可撤销，之后匿名化。
5. 三套主题逐页走查：设计稿目录里每个 MVP 页面跑一次 /design-check，最后汇总还剩哪些差异。
6. 联调和测试：补齐关键流程的端到端测试；把需要我在微信开发者工具和真机上手动检查的项目列成清单。

验收：所有 MVP 页面三套主题都走查过；关键流程的端到端测试通过。最后跑 /phase-done 4。
```

## 阶段 5 · 第 9 周：提审

```text
帮我做提审前检查：
1. 对照 docs/platform-checklist.md，列出还没办的事。
2. 找出代码里用到的所有隐私接口，和小程序后台要填的「用户隐私保护指引」逐条对上，列给我。

4. 写一份提审说明草稿：产品定位是「活动日程工具」，写清审核人员怎么测试。
5. 打一个体验版的构建，告诉我在微信开发者工具里怎么上传。
```

## 平时常用

**修 bug**
```text
现象：……（贴截图或报错原文）
复现步骤：……
期望：……
先写一个能复现这个问题的测试，确认它失败；再找到根因修好，不要只是把报错压住；最后跑相关测试给我看结果。
```

**加新需求（先让它问清楚）**
```text
我想加一个功能：……
先用 AskUserQuestion 一项一项问我，把细节、边界情况和取舍问清楚。问完写到 docs/specs/<功能名>.md，并在 docs/decisions.md 里加一条（写上日期）。写完就停，我会开一个新会话再实现。
```

**审查这次改动**
```text
用子代理在新的上下文里审查这次的改动，对照 docs/spec.md 和 docs/decisions.md。只报会让功能出错或违反规则的问题，不报风格偏好。
```

**页面走查、阶段验收**
```text
/design-check PlanDetail
/phase-done 2
```

## V1.1 以后

首版上线、种子群数据过了门槛再开始。每一项都按「先读方案和设计稿 → 计划模式出方案 → 我确认 → 写代码和测试 → /phase-done」来，例如：

```text
开始做 V1.1 的 AA 记账。先读 docs/spec.md「功能规划 · AA 记账」和设计稿 PlanEnded、AddBill、BillDetail、Settled、PayBack、Ledger。金额用整数「分」存；平均、份数、自定义三种分摊和最少转账方案都要有单元测试；多币种分开算。先在计划模式里给我方案。
```

其他 V1.1 项目：管理员角色、发起人转交、事后点名（隐形鸽）、正向徽章、鸽王殿、通缉令海报、分享卡片加强版（动态消息，看第 5–6 周的实测结论再决定）。
